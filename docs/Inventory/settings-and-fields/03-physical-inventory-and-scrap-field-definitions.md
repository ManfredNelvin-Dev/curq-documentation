# Physical Inventory and Scrap Field Definitions

This document provides a comprehensive data dictionary for physical inventory adjustments, cycle count registers, scrap orders, and stock write-offs in CURQ Inventory.

---

## 1. Physical Inventory Adjustments Register Data Dictionary

The Physical Inventory Adjustments register itemizes theoretical stock balances, counted quantities, and reconciliation actions:

| Field Name | Description |
| :--- | :--- |
| **Product** | Catalog item name and specification being audited during the physical inventory count. |
| **Lot/Serial Number** | Specific tracking identifier for items managed by lot batches or unique serial numbers. |
| **On Hand Quantity** | Theoretical stock balance calculated by CURQ from cumulative historical transfers. |
| **Unit of Measure (UoM)** | Measurement unit applied to the product quantity *(e.g., `Units`)*. |
| **Counted Quantity** | Editable field capturing the actual physical quantity counted on shelves by the audit team. |
| **Difference** | Calculated variance reflecting surplus *(positive value)* or shrinkage *(negative value)*. |
| **Scheduled Date** | Planned target date for completing the physical inventory audit task. |
| **User** | Assigned warehouse specialist or inventory auditor responsible for the cycle count. |

---

## 2. Scrap Orders Register Data Dictionary

The Scrap Orders register itemizes all historical and active stock write-offs:

### 2.1 Register Columns

| Field Name | Description |
| :--- | :--- |
| **Reference** | Unique alphanumeric identifier assigned to the scrap order upon creation *(e.g., `REF0001`, `SP/00001`)*. |
| **Date** | Timestamp recording the date and time when the scrap transaction was initiated or executed. |
| **Product** | Relational link displaying the catalog item written off to scrap. |
| **Quantity** | Numeric count of units discarded from inventory. |
| **Unit of Measure** | Standard measurement unit applied to the scrapped product quantity *(e.g., `Units`, `kg`)*. |
| **Status** | Operational lifecycle stage badge (*Draft*, *Done*). |

---

## 3. Scrap Order Form Fields and Action Controls Data Dictionary

The Scrap Order form captures product specifications, disposal quantities, replenishment triggers, and scrap justifications:

### 3.1 Scrap Order Fields

| Field Name | Description |
| :--- | :--- |
| **Product** | Mandatory relational field selecting the inventory catalog item to be scrapped *(e.g., `Fair Phone 5 (Black)`)*. |
| **Quantity** | Mandatory numeric field specifying the exact number of units to be deducted from stock *(e.g., `2.00`)*. |
| **Replenish Quantities** | Optional toggle instructing CURQ replenishment rules to automatically reorder replacement stock for the scrapped units. |
| **Scrap Reason** | Optional descriptive field or dropdown recording the root cause of the write-off *(such as transit damage, defect, or expiration)*. |
| **Source Document** | Optional reference field linking the write-off to an originating transfer *(e.g., `WH/IN/00070`)* or quality ticket. |

### 3.2 Scrap Order Action Buttons

| Button | Behavior |
| :--- | :--- |
| **Validate** | Commits the scrap write-off, deducts stock from storage, posts valuation entries, and advances status to **Done**. |

---

## 4. Validated Scrap Order and Smart Controls Data Dictionary

Following validation, CURQ freezes operational parameters, logs immutable timestamps, and exposes relational move buttons:

### 4.1 Validated Scrap Fields

| Field Name | Description |
| :--- | :--- |
| **Order Reference** | System-generated tracking code displayed as the form header upon validation *(e.g., `SP/00001`)*. |
| **Product** | Locked catalog item that was scrapped *(e.g., `Fair Phone 5 (Black)`)*. |
| **Quantity** | Locked unit count and unit of measure deducted from stock *(e.g., `2.00 Units`)*. |
| **Replenish Quantities** | Checkbox indicating whether automated replenishment was triggered for the scrapped units. |
| **Scrap Reason** | Tag recording the verified cause of the write-off *(e.g., `Transit Damage`)*. |
| **Source Document** | Optional originating transfer or reference document linked to the scrap order. |
| **Date** | Immutable timestamp recording when the scrap order was validated *(e.g., `11/06/2026 15:15:55`)*. |

### 4.2 Validated Smart Buttons

| Button | Behavior |
| :--- | :--- |
| **Product Moves** | Opens the balanced double-entry stock moves generated by the scrap write-off. |

---

## 5. Scrap Moves History Register Data Dictionary

Clicking the Product Moves smart button opens the Moves History register itemizing source and destination coordinates:

| Field Name | Description |
| :--- | :--- |
| **Date** | Timestamp of physical movement execution *(e.g., `11/06/2026 15:15:55`)*. |
| **Reference** | Transactional reference code linking to scrap record `SP/00001`. |
| **Product** | Specific catalog item transferred *(e.g., `Fair Phone 5 (Black)`)*. |
| **Lot/Serial Number** | Tracking identifier if the scrapped item is managed by lots or serial numbers. |
| **From** | Source warehouse location decremented during write-off *(e.g., `WH/Stock`)*. |
| **To** | Virtual destination location credited during write-off *(e.g., `Virtual Locations/Scrap`)*. |
| **Quantity** | Stock quantity deducted, styled in red text *(e.g., `2.00 Units`)* to indicate inventory reduction. |
| **Status** | Finalized execution badge (*Done*). |

---

## 6. Stock Move Record Form Data Dictionary

Drilling down into an individual move row displays detailed operational accountability:

| Field Name | Description |
| :--- | :--- |
| **Date** | Execution timestamp matching the scrap order completion date. |
| **Reference** | Unique identifier for this individual stock transfer *(e.g., `SP/00001`)*. |
| **Source** | Originating business document triggering the physical movement. |
| **Product** | Catalog description of the material transferred. |
| **Quantity** | Exact unit count moved between locations *(e.g., `2.00 Units`)*. |
| **Done By** | User identity logging the warehouse operator who validated the move. |
